# アプリケーション機能・画面仕様書：マゴノテlink

---

## 1. アプリの名前と目的

- **アプリ名**: マゴノテlink
- **目的・概要**:
  - 肉体労働が困難な高齢者や管理コストを減らしたい自治体と、金銭的ニーズを持つ高校生をマッチングし、草刈りや清掃などの作業を通じて報酬を得られる仕組みを提供する。
  - 学校や自治体が身元を保証する仕組みを取り入れることで、高齢者・地元企業の不安を解消し、地域の景観悪化・管理不足の課題を解決する。

## 4. 仮のデータ仕様

全画面で共通して使用するデータは、実在しない架空のデータに統一します。

- **ユーザー名**: `利用者A`（自分）、`○○さん`、`△△さん`、`□□さん`（メッセージ相手）
- **作業地域・住所**: `サンプル県サンプル市サンプル町1-1`（表示例：`浜田市○○町○-○`）
- **作業内容**: `草刈り`
- **報酬・時給**: `1,000円`
- **指定時間**: `なし`
- **支払方法**: `現金`
- **期日表示**: `期日まで残り1日`

## 6. 開発および実装上の守る条件

1. **技術スタック**:
   - HTML・CSS・JavaScript のみを使用する。
   - データベース・ユーザー認証・ログイン機能は実装しない。
2. **ファイル構成と構造**:
   - 画面ごとに独立したHTMLファイルを作成する（初期画面は `index.html`）。
   - CSSは `style.css`、JavaScriptは `script.js` のそれぞれ1ファイルに統一し、すべてのHTMLファイルで読み込む。
   - ファイルのパス参照およびページ移動は、すべて `./` から始まる相対パスを使用する（例: `./style.css`, `./job_list.html`）。
3. **デザイン・表示要件**:
   - スマートフォン（モバイル端末）での閲覧に適した画面幅・レイアウトとする。
   - ワイヤーフレーム上の `（確定する）` 等のカッコ書きは仮の記号であるため、実際の画面では `確定する` と括弧なしで表示する。
   - 画面遷移図に記載のある案内メッセージ（例：「申しこみ完了後」「作成完了後」など）は、対応する遷移動作の文脈に合わせて画面内またはメッセージとして表示する。
4. **機能追加の制限**:
   - ワイヤーフレームおよび画面遷移図に掲載されていない機能や画面は一切追加しない。

## 7. 確認したいこと（図に記載のない仕様・未決定事項）

1. **全画面ヘッダーの「ユーザーアイコン」タップ時の挙動**:
   - ワイヤーフレームでは各画面のヘッダー右側に「ユーザーアイコン」が配置されていますが、遷移図上ではホーム画面以外からの明確な矢印が描かれていません。
   - **仮の対応方針**: 全画面のヘッダーにあるユーザーアイコンをタップした場合は `./account.html`（アカウント設定画面）へ直接遷移する設計とします。
2. **「予約履歴」から「評価画面」への遷移トリガー**:
   - 遷移図上では「予約履歴」と「評価画面」相互に矢印が引画されていますが、ワイヤーフレームの「予約履歴」画面内には評価ボタンが明記されていません。
   - **仮の対応方針**: 予約履歴のカード内に「評価する」ボタンを仮配置して `./review.html` に遷移できるようにします。
3. **「依頼作成・編集」画面の「削除」ボタンの遷移先**:
   - ワイヤーフレーム下部に「削除」ボタン（ゴミ箱アイコン）がありますが、遷移図に行き先矢印がありません。
   - **仮の対応方針**: ボタン押下時はJavaScriptの `confirm()` ダイアログ等で確認表示を行い、同画面（`./job_manage.html`）に留まる仕様とします。
4. **検索バー・お気に入り（ハート）ボタンの動作**:
   - 依頼一覧の検索バーやハートアイコン等のインタラクティブ要素についてはバックエンドが存在しないため、フロントエンド（JavaScript）での見かけ上の表示切り替えのみ（例: ハートの色の反転）とします。
